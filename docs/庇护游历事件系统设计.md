# 庇护凡人 / 游历 / 事件系统 · 完整方案

本文档定义「游历 → 事件 → 庇护 → 上供」闭环。
所有数值集中在 `config/travel.json`（模式与槽位）、`config/travel_events.json`（事件库）、`config/materials.json`（材料）、`config/patron.json`（庇护与上供），本文档标注归属，便于调参。
与 `docs/api.md`、`docs/database.md`、`docs/修仙游戏设计方案.md` 保持一致，冲突时以本文档为准。

> 境界 id 说明：本文档统一使用项目实际境界 id `qi / zhuji / jindan / yuanying / huashen`（见 `config/realms.json`）。

---

## 一、整体闭环

```
达到筑基 → 开放游历 → 选择游历模式 → 等待产出事件
    → 事件进入槽位（最多 4 个）→ 玩家查看详情
    → 处理事件 → 获得庇护对象（凡人 / 小宗门 / 大宗门 / 超级宗门）
    → 按周期上供灵石 → 玩家手动领取
```

核心原则：

- 庇护凡人 = 纯数字，有上限，低收益。
- 庇护宗门 = 有名额上限，高收益，可遇不可求。
- 游历越久，事件品质越高。
- 事件暂不接入战斗，先直接完成；战斗模块上线后再补门槛。
- 上供手动领取，不自动入账，防止无限挂机。

## 二、游历系统

### 2.1 开放条件

- 默认无庇护。
- 玩家达到 **筑基** 后开放游历。
- 开放条件放 `config/unlock.json`（本模块登记 `travel` 项），`travel.json` 不重复存放。

### 2.2 游历模式

| 模式     | 耗时    | 事件品质           | 定位     |
| -------- | ------- | ------------------ | -------- |
| 普通游历 | 10 分钟 | 普通事件为主       | 碎片时间 |
| 深度游历 | 2 小时  | 高品质事件概率更高 | 挂机     |

配置归属：`config/travel.json`

```json
{
  "modes": [
    {
      "id": "normal",
      "name": "普通游历",
      "duration_minutes": 10,
      "event_weights": { "common": 80, "rare": 18, "epic": 2 }
    },
    {
      "id": "deep",
      "name": "深度游历",
      "duration_minutes": 120,
      "event_weights": { "common": 40, "rare": 45, "epic": 15 }
    }
  ]
}
```

### 2.3 事件槽位

- 前端最多显示 4 个事件槽。
- 游历完成后，产出的事件进入空槽。
- 槽满时禁止游历，但玩家可以放弃旧事件腾出空位。
- 槽位上限可配置。

配置归属：`config/travel.json`

```json
{
  "max_event_slots": 4
}
```

### 2.4 事件有效期

- 事件有有效期，默认 3 天，可配置。
- 过期事件自动消失，不产出任何奖励。
- 玩家也可主动放弃事件。

配置归属：`config/travel.json`

```json
{
  "event_expire_days": 3
}
```

### 2.5 游历流程

1. 玩家选择游历模式。
2. 记录开始时间，扣除时间（离线/在线均可累积）。
3. 到达时间后，按 `event_weights` 抽取品质，再按品质内 `weight` 抽取具体事件。
4. 事件写入事件槽，记录生成时间与过期时间（抽中「无事发生」时不占槽）。
5. 玩家点击事件查看详情并处理。

本期游历不消耗任何资源。

## 三、事件系统

### 3.1 事件类型

| 类型             | 说明                 | 产出                    |
| ---------------- | -------------------- | ----------------------- |
| 凡人求助         | 遇到凡人，可庇护     | 少量下品灵石上供        |
| 邪物攻打小宗门   | 帮助小宗门，可庇护   | 中品 + 部分下品灵石上供 |
| 邪物攻打大宗门   | 帮助大宗门，可庇护   | 上品 + 部分中品灵石上供 |
| 邪物攻打超级宗门 | 帮助超级宗门，可庇护 | 极品 + 部分上品灵石上供 |
| 偶得灵石         | 无庇护，直接给资源   | 一次性灵石              |
| 无事发生         | 空事件               | 无                      |

事件品质越高，可庇护对象等级越高，上供越好，但处理门槛也越高。

### 3.2 事件品质

| 品质   | 说明                          | 品质权重示例（普通/深度） |
| ------ | ----------------------------- | ------------------------- |
| common | 普通事件，凡人为主            | 80 / 40                   |
| rare   | 稀有事件，小宗门为主          | 18 / 45                   |
| epic   | 史诗事件，大宗门/超级宗门为主 | 2 / 15                    |

### 3.3 事件处理

- 本期不接入战斗与难度判定，事件直接完成。
- 后续接入战斗后，事件需要满足战斗力 + 时间门槛才能完成（届时在事件配置里新增字段与判定逻辑）。
- 门槛按事件品质和庇护对象等级配置。
- 有机遇遇到高等级宗门，但玩家等级低时完成概率极低（如 1%）。

配置归属：`config/travel_events.json`

```json
{
  "events": [
    {
      "id": "mortal_bandit_3",
      "name": "三个女孩被土匪敲诈",
      "quality": "common",
      "type": "patron_mortal",
      "weight": 8,
      "desc": "三名女孩被土匪围住敲诈，你出手相救。",
      "reward": { "patron_mortal": 3 }
    },
    {
      "id": "sect_small_9",
      "name": "邪物攻打青云门",
      "quality": "rare",
      "type": "patron_sect",
      "weight": 6,
      "desc": "青云门虽是小宗门，却富甲一方，邪物来犯，你出手相助。",
      "reward": { "patron_sect": "small" }
    },
    {
      "id": "resource_herb_2",
      "name": "崖边灵草",
      "quality": "rare",
      "type": "resource",
      "weight": 6,
      "desc": "崖边有一株百年灵草，你冒险采下。",
      "reward": { "item": { "id": "lingcao_100", "quantity": 1 } }
    },
    {
      "id": "nothing_1",
      "name": "一路畅通",
      "quality": "common",
      "type": "nothing",
      "weight": 10,
      "desc": "今日游历青山，一路畅通无阻，无事发生。",
      "reward": null
    }
  ]
}
```

说明：

- 事件库与模式/槽位分离：`travel.json` 只放 `modes`、`max_event_slots`、`event_expire_days`，事件全部放 `travel_events.json`。
- `type` 取值：`patron_mortal`（凡人庇护）、`patron_sect`（宗门庇护）、`resource`（一次性灵石或储物戒物品）、`nothing`（无事发生，不占槽位）。
- `weight` 为该事件在所属品质内的抽取权重，缺省为 1（等权）。
- `desc` 为事件文案，前端在事件槽点「查看」时展示。
- `reward` 定义事件完成后的产出：`resource` 用 `stones` 发灵石、用 `item`（`{ id, quantity }`）发储物戒物品；材料名与类别取自 `config/materials.json`。
- 高等级宗门事件出现概率低，且完成概率受玩家境界影响（后续接入）。

## 四、庇护系统

### 4.1 庇护凡人

凡人庇护是纯数字，有上限。每庇护一个凡人，按周期产出少量下品灵石。

配置归属：`config/patron.json`

```json
{
  "mortal": {
    "max_count": 100,
    "supply_interval_hours": 6,
    "supply_per_capita_low": 0.1,
    "max_accumulate": 4
  }
}
```

说明：

- `max_count` 凡人庇护上限；
- `supply_interval_hours` 上供周期；
- `supply_per_capita_low` 每人每周期产出的下品灵石；
- `max_accumulate` 最多累积周期数，防止无限挂机；
- 结算取整：`floor(数量 × 每人产出 × 已结算周期数)`，不足 1 直接舍去（低收益靠量）。

### 4.2 庇护宗门

宗门分三级：小宗门、大宗门、超级宗门。宗门庇护有名额上限，随玩家大境界提升而增加。
每个宗门独立上供，产出对应品级灵石。名额满时，需解除一个才能庇护新的。

名额上限规则：

| 玩家境界 | 宗门庇护上限        |
| -------- | ------------------- |
| 筑基     | 1                   |
| 金丹     | 2                   |
| 元婴     | 3                   |
| 化神     | 4                   |
| ……       | 每提升一个大境界 +1 |

配置归属：`config/patron.json`

```json
{
  "sect": {
    "max_count_by_realm": {
      "zhuji": 1,
      "jindan": 2,
      "yuanying": 3,
      "huashen": 4
    },
    "levels": {
      "small": {
        "name": "小宗门",
        "supply_interval_hours": 6,
        "supply": { "low": 50, "mid": 5 },
        "max_accumulate": 4
      },
      "large": {
        "name": "大宗门",
        "supply_interval_hours": 6,
        "supply": { "mid": 50, "high": 5 },
        "max_accumulate": 4
      },
      "super": {
        "name": "超级宗门",
        "supply_interval_hours": 6,
        "supply": { "high": 50, "top": 5 },
        "max_accumulate": 4
      }
    }
  }
}
```

说明：

- `max_count_by_realm` 按大境界配置宗门庇护上限；
- `levels` 按宗门等级配置上供；
- `supply` 定义每周期产出的灵石品级与数量；
- `max_accumulate` 最多累积周期数；
- 同等级宗门允许叠加多行，上供逐行独立计算。

### 4.3 庇护解除

解除宗门庇护统一使用商店道具「断缘令」，不使用灵石赔偿。

- 道具名称：断缘令（`duan_yuan_ling`）。
- 道具定位：解除与宗门的庇护关系，需支付该道具。
- 商店价格：本期 500 中品灵石、不限购。
- 所需道具数量按宗门等级：小 1 / 大 2 / 超级 3。

配置归属：`config/patron.json`

```json
{
  "release": {
    "item_id": "duan_yuan_ling",
    "compensation_by_level": { "small": 1, "large": 2, "super": 3 }
  }
}
```

`config/shop.json` 追加商品：

```json
{
  "id": "duan_yuan_ling",
  "name": "断缘令",
  "category": "talisman",
  "ref_id": "duan_yuan_ling",
  "price": 500,
  "currency_level": "mid",
  "limit": null,
  "unlock": null
}
```

## 五、上供结算

### 5.1 结算方式

- 按周期结算，支持离线累积。
- 玩家上线后手动领取，不自动入账。
- 累积有上限，超过不再累积。
- 手动领取的目的：防止玩家长期挂机自动入账。

### 5.2 结算流程

1. 计算当前时间与上次结算时间的间隔。
2. 按周期数计算产出。
3. 受 `max_accumulate` 限制（超出周期丢弃，`last_supply_at` 追平到当前）。
4. 玩家点击领取，产出写入灵石。
5. 受 `spirit_stone_caps` 限制，超出上限部分直接丢弃。
6. 更新上次结算时间。

### 5.3 与灵石上限的衔接

上供产出同样受 `spirit_stone_caps` 限制，超出上限的部分直接丢弃。
这进一步推动玩家兑换高品灵石。

## 八、落地决策

> 本节记录规格之外、实现时确定的具体决定，便于后续追溯与调参。

1. **落地范围**：本期后端 + 前端全覆盖（配置、数据表、服务层、接口、前端页面与入口）。
2. **断缘令**：本期直接上架商店并给默认价 —— **500 中品灵石、不限购**；小/大/超级宗门分别消耗 **1/2/3** 个。
3. **事件补全**：除规格中的四条宗门/凡人事件外，补上 `fortune_stones`（偶得灵石，一次性给灵石）与 `nothing`（无事发生，空事件）两条配置。
4. **境界 id 修正**：规格文档里的 `zhu_ji/jin_dan/yuan_ying/hua_shen` 与项目实际不符，统一改为 `zhuji/jindan/yuanying/huashen`。
5. **`nothing` 不占槽位**：抽中「无事发生」时本次游历不产出事件，直接消耗掉这次游历结果。
6. **宗门名额与凡人上限的处理**：事件处理时若名额/上限已满，返回对应错误码并**保留事件在槽位**，不消耗事件。
7. **游历的状态限制**：游历仅在 `idle`（空闲）与 `retreating`（闭关中）可开始，**冥想中（meditating）禁止外出游历**；除状态外还受「已有游历进行中」「事件槽已满」限制。实现上复用 `GameService::ACTION_STATUS`（新增 `travel => ['idle','retreating']`）并把 `guard()` 改为 public 供 `TravelService` 调用，保证后端权威拦截、前端按钮仅作体验优化。
8. **数据表**：新增 `travels`、`player_events`、`player_patrons` 三张表；`player_patrons` 不加 `(player_id, kind, sect_level)` 唯一索引，同等级宗门可叠加多行，上供逐行计算。
9. **上供领取周期处理**：领取时按「已过整周期数」计算，`max_accumulate` 之外的周期直接丢弃，`last_supply_at` 追平到当前周期边界。
10. **凡人上供取整**：`floor(count × supply_per_capita_low × appliedCycles)`，不足 1 舍去。
11. **前端入口调整**：游历不再单独占一个页面，直接并入主页面（洞府）展示；庇护信息并入用户信息区，凡人 / 宗门各占一个属性格，点击展开 `PatronPanel` 查看收益明细与领取。
12. **事件库落地（54 条）**：事件从 `travel.json` 拆到 `config/travel_events.json`，含凡人求助 12 条、小宗门 12 条、大宗门 5 条、超级宗门 3 条、纯资源 12 条、无事发生 10 条；每级宗门事件文案不同（豪华小宗门以文案与权重体现，不单独标记）。新增 `type = resource`（产出灵石或储物戒物品）与 `config/materials.json`（灵草·十年/百年，不上架坊市）；`type = none` 改名 `nothing`。本期不做难度判定与 `require` 门槛（战斗未上线），事件处理后直接完成；前端事件槽「查看」时展示 `desc`。
