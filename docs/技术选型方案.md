# 文字修仙 · 技术选型方案

> 形态：正常 Web 前端项目（Vue SPA + PHP 后端）
> 核心理念：游戏逻辑数据驱动，前后端分离，你的 PHP 技能栈全覆盖

---

## 一、架构总览

```
浏览器 (Vue3 SPA)
   ↓  HTTP/JSON
Nginx (静态资源 + 反向代理)
   ↓
Webman API (PHP 常驻内存)
   ↓
MySQL (玩家存档)  +  Redis(短期计数)
```

- 前端 Vue3 单页应用，游戏逻辑主要在前端（实时响应）
- 后端 Webman 负责持久化、离线结算、校验、排行榜
- 前后端通过 REST API 通信，JSON 数据格式

---

## 二、前端技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Vue 3 + Vite | 你会 Vue；Vite 构建快、AI 生成友好 |
| 状态管理 | Pinia | 全局状态（境界/修为/寿元/闭关计时）需要集中管理 |
| 语言 | TypeScript（可选） | 游戏逻辑复杂，类型防错；纯 JS 也能跑 |
| UI | 手写 CSS + 轻量组件 | 减法原则，不需要重型 UI 库 |
| 请求 | axios / fetch | 调后端 API |

### 前端模块划分

```
src/
├── game/              # 纯逻辑层（不依赖 DOM，方便测试）
│   ├── state.ts       # 玩家状态（境界/修为/寿元/灵石）
│   ├── economy.ts     # 数值计算（冥想/闭关收益）
│   ├── events.ts      # 事件引擎（奇遇/遗迹随机）
│   ├── time.ts        # 时间系统（1天=2年、离线结算）
│   └── api.ts         # 后端接口封装
├── data/              # 内容层（AI 批量生成的 JSON）
│   ├── realms.json    # 境界体系
│   ├── events.json    # 事件池（奇遇/遗迹/宗门）
│   ├── pills.json     # 丹药
│   └── formations.json# 法阵
├── views/             # Vue 页面（主界面/闭关/遗迹）
├── components/        # Vue 组件
└── main.ts            # 入口
```

**分层原则：数据与逻辑分离** —— AI 生成的 JSON 事件池、逻辑层、UI 层互相独立：改文案不碰代码，改逻辑不碰 UI。

## 三、后端技术选型

### 推荐：Webman（而非 Laravel）

| 维度 | Webman | Laravel |
|---|---|---|
| 运行模型 | 常驻内存（workerman） | PHP-FPM 传统 |
| 高并发 | 强 | 一般 |
| 定时任务/长连接 | 天然支持 | 需额外配置 |
| 开发速度 | 较高 | 高（生态全） |

**选择 Webman 的关键理由：本游戏核心机制「时间流逝 + 离线结算」是常驻计算场景**：

- 寿元随真实时间流逝 → 需要常驻进程实时结算
- 闭关 24-48 小时到期判定 → 常驻进程里的定时器即可实现，无需 cron
- Webman 基于 workerman，内存常驻，天然适合游戏后端

### 后端职责

- 玩家存档 CRUD（MySQL）
- 离线时间结算（寿元流逝、闭关完成）
- 防作弊（前端数值服务端校验）
- 排行榜
- 实名接口对接（取年龄，不存原始身份证号）

### 技术栈

- PHP 8+ / Webman 框架
- MySQL 8（玩家数据）
- Redis（每日转世次数等短期计数）

## 四、存储设计

### MySQL 主要表（初版）

| 表 | 内容 |
|---|---|
| users | 玩家账号、实名年龄、注册时间 |
| players | 玩家游戏状态（境界/修为/寿元/灵石，JSON 或字段） |
| save_data | 存档明细（必要时拆分） |
| events_log | 玩家事件记录（可选） |
| rankings | 排行榜（可选） |

### 存档策略

- 前端游戏过程实时跑，周期性地/关键节点调用后端存盘点
- 离线结算：玩家下次请求时，后端根据「最后活跃时间」结算寿元流逝/闭关进度
- Redis：只存每日转世次数等带过期时间的短期计数，不作为游戏存档来源

## 五、实名认证（绑定身份证取年龄）

### 原则：不收集、不存储原始身份证号

- 接入第三方实名认证接口（如网易易盾等有资质服务商）
- 接口只返回「是否实名 + 出生年份（年龄）」
- 用真实年龄驱动寿元机制（见设计文档第七章）
- 未成年人特殊处理：防沉迷限制 + 寿元机制调整

## 六、部署

```
服务器
├── Nginx       # 前端静态 + 反代 /api
├── Webman      # 常驻进程模式（非 FPM）
└── MySQL / Redis
```

- 前端 `npm run build` 产物部署到 Nginx 静态目录
- Webman 以常驻进程启动（`php start.php start`），可配 systemd 守护
- 可选 Docker 容器化

## 七、AI 生产流程

### AI 的两个角色

| 角色 | 产出 | 工具 |
|---|---|---|
| 代码生成 | Vue 组件、游戏引擎、Webman 接口 | Trae |
| 内容生成 | 事件池 JSON、文案、数值建议 | AI prompt |

### 内容生成 prompt 模板（示例）

```
你是修仙题材文案生成器，输出 JSON 格式事件池，字段：
{ id, type(奇遇/遗迹/宗门), title, text, options:[{label, effect}] }
要求：
- 文案精炼、仙侠腔、每段不超过50字
- 每个事件2-3个选项，数值影响明确
- 批量生成 100 条，境界分布均匀
```

### 工作流建议

1. 先用 Trae 搭出「骨架版」（冥想+闭关+突破最小闭环）
2. 验证核心循环手感
3. AI 批量补内容（事件池、境界文案）
4. 上后端（存档 + 离线结算 + 实名）
5. 逐步加内容（遗迹探索、宗门争锋）
