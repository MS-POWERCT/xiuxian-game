# 游戏业务模块设计 · 灵石 / 商店 / 储物戒

> 本文档定义「灵石 / 商店 / 储物戒」三个业务模块的设计。
> 所有数值集中在 `config/*.json`，本文档标注每项配置的归属，便于调参。
> 与 `docs/api.md`、`docs/database.md`、`docs/修仙游戏设计方案.md` 保持一致，冲突时以本文档为准。

## 一、灵石系统

### 1.1 灵石分级

引入四级灵石，参考凡人修仙传：

| 品级 | 名称     | 价值基准   |
| ---- | -------- | ---------- |
| 1    | 下品灵石 | 1          |
| 2    | 中品灵石 | 100 下品   |
| 3    | 上品灵石 | 100 中品   |
| 4    | 极品灵石 | 100 上品   |

- 相邻品级兑换比例 **1 : 100**（固定，不随活动变动）。
- 玩家持有灵石按 4 个品级**分开计数**，不合并成单一总数。

### 1.2 存储方案（方案 C）

灵石采用 **JSON 字段** 存储，不拆成四个独立字段，也不放进储物戒。

`players.spirit_stones`：

```json
{ "low": 0, "mid": 0, "high": 0, "top": 0 }
```

- 下品、中品、上品、极品均为货币，不是物品。
- 储物戒只放物品，不放灵石。
- 所有灵石变动必须走统一服务层，禁止业务代码直接改字段。

统一服务层接口：

- `getSpiritStones(playerId)`
- `addSpiritStones(playerId, level, amount)`
- `spendSpiritStones(playerId, level, amount)`
- `exchangeSpiritStones(playerId, fromLevel, toLevel, amount)`

### 1.3 灵石上限与丢弃规则

每种品级灵石都有独立上限。到达上限后，**新获得的灵石直接丢弃**，不进入背包、不折算、不提示补发。

- 目的：强制玩家把低品灵石兑换成高品灵石，避免低品无限堆积。
- 上限按品级分别配置，可调。

配置归属：`config/economy.json`

```json
{
  "spirit_stone_levels": ["low", "mid", "high", "top"],
  "spirit_stone_caps": {
    "low": 1000000,
    "mid": 1000000,
    "high": 1000000,
    "top": 1000000
  }
}
```

> 说明：
>
> - `spirit_stone_caps` 每个品级一个上限；
> - 超出上限的部分直接丢弃，不进入任何记录；
> - 上限值后续可按品级分别调整。

### 1.4 兑换规则

- **升级兑换（低→高）**：1 高品 = 100 低品 + 手续费。
  - 手续费 = 兑换额 × 对应兑换对的手续费比例，额外消耗**低品灵石**。
- **降级兑换（高→低）**：1 高品 = 100 低品，**免手续费**。
- **部分商品/消耗强制要求指定品级**（见商店模块），不能只靠总数折算，必须持有对应品级。

手续费**按兑换对分别配置**，不是全局单一比例。例如：

- 下品 → 中品：5%
- 中品 → 上品：10%
- 上品 → 极品：15%

配置归属：`config/economy.json`

```json
{
  "exchange_ratio": 100,
  "exchange_fee_ratio": {
    "low_to_mid": 0.05,
    "mid_to_high": 0.10,
    "high_to_top": 0.15
  }
}
```

> 说明：
>
> - `exchange_ratio` 固定为 100；
> - `exchange_fee_ratio` 按兑换对配置，每个兑换对独立；
> - 降级兑换不收手续费；
> - 手续费额外消耗低品灵石，不占用兑换本金。

### 1.5 灵石用途

**本期不做灵石用途。** 只完成灵石分级、存储、上限、兑换四项基础能力，为后续商店、闭关、改名等消耗场景预留接口。

## 二、商店系统

### 2.1 定位

商店是灵石的主要消耗出口，玩家用**对应品级**的灵石购买物品。

### 2.2 本期商品

本期只上架一个商品：**聚气散**。

| 分类 | 商品   | 作用               | 建议品级 | 货币要求 |
| ---- | ------ | ------------------ | -------- | -------- |
| 丹药 | 聚气散 | 冥想/悟道修为小幅加成 | 下品     | 下品灵石 |

### 2.3 商店机制

- 商品列表集中配置 `config/shop.json`。
- 每个商品含：id、名称、分类、ref_id、价格、currency_level、限购、上架条件。
- 上架解锁：达到某境界才出现（本期可先不启用）。
- 限购：本期可先不启用。
- 买入入账：购买后写入储物戒（见第三节）。
- 暂不做卖出/回收。

配置归属：`config/shop.json`

```json
{
  "items": [
    {
      "id": "juqi_san",
      "name": "聚气散",
      "category": "pill",
      "ref_id": "juqi_san",
      "price": 10,
      "currency_level": "low",
      "limit": null,
      "unlock": null
    }
  ]
}
```

> 说明：
>
> - `price` 为对应品级灵石的数量；
> - `currency_level` 指定必须使用的灵石品级；
> - `limit` 与 `unlock` 本期可置空，后续扩展。

### 2.4 购买流程

1. 校验商品是否存在、是否上架、是否限购。
2. 校验玩家对应品级灵石是否足够。
3. `spendSpiritStones` 扣灵石。
4. `addItem` 写入储物戒。
5. 返回购买结果。

## 三、储物戒（背包系统）

### 3.1 定位

储物戒只放**物品**，不放灵石。

| 放                             | 不放                       |
| ------------------------------ | -------------------------- |
| 丹药、法阵、功法、符箓、材料    | 下品/中品/上品/极品灵石     |

### 3.2 存储结构

使用一张通用表 `player_items`：

| 字段         | 含义                                            |
| ------------ | ----------------------------------------------- |
| `id`         | 主键                                            |
| `player_id`  | 玩家                                            |
| `item_id`    | 物品 id（对应 shop.json / pills.json 等）        |
| `category`   | pill / formation / technique / talisman / material |
| `quantity`   | 数量                                            |
| `created_at` | 获得时间                                        |
| `updated_at` | 更新时间                                        |

唯一索引：`(player_id, item_id)`，同一物品叠加数量。

### 3.3 最小接口

- `addItem(playerId, itemId, category, quantity)`
- `removeItem(playerId, itemId, quantity)`
- `getItems(playerId, category?)`
- `hasItem(playerId, itemId, quantity)`

### 3.4 与商店的衔接

- 商店购买成功 → `spendSpiritStones` → `addItem`。
- 后续闭关/突破消耗物品 → `hasItem` → `removeItem`。
- 暂不做玩家间交易和卖出。

## 七、落地决策（与用户确认）

1. **落地范围**：后端 + 前端全覆盖（配置、数据库、服务层、接口、前端界面）。
2. **旧数据迁移**：现有 `players.spirit_stones` 的 INT 旧值**整体记为下品灵石**，不损失玩家资产。
3. **闭关计价**：本期闭关**不再消耗灵石**（移除法阵/丹药的灵石扣费）；后续改为消耗储物戒中的物品。
